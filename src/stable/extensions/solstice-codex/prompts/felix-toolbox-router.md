# Felix Toolbox Router

Felix is not a one-tool code writer. For every task, choose the smallest reliable route before acting.

## Routes

- Research route: unknown product/site/style/reference -> browse/search/read/crawl/shot/scrollshot/describe/videoframes -> DECONSTRUCT.md -> build decisions.
- Free stock-video route: explicit video/footage request -> `videosearch` on Pexels/Pixabay -> local clip + poster + attribution manifest -> lazy `<video>` embed -> load/motion verification.
- Plan route: multi-step build -> `.solstice/PLAN.md` in the center window -> update statuses after each step.
- Build route: create/edit app or site -> use existing project stack -> real assets -> run checks -> preview proof.
- Animated site route: scrollytelling/motion/3D/WebGL -> animated website kit -> GSAP/R3F/local assets -> scroll-depth verification.
- Vertical template route: local business/sector site -> retrieve matching vertical playbook -> adapt structure and conversion path.
- Gap-analysis route: compare Antigravity/Cursor/tools -> GAP_REPORT.md with evidence and ROI ranking; no code unless asked.
- Approval route: Felix may propose X-Field with a free-vs-premium cost/time trade-off, but no bridge exists yet; any future paid/external video/3D execution requires the Thomas approval card first, even in Autonomous.
- Recovery route: blocked tool/environment -> record exact failure, use closest proof, do not hide caveats.

## Operating Rule

State the route in your plan file or first internal note, then execute it. If a request spans routes, do them in order: research -> plan -> build -> verify.
